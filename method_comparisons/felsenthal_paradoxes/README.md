# felsenthal_paradoxes — Felsenthal's paradox examples, run for real

Worked examples from Dan S. Felsenthal, *"Review of Paradoxes Afflicting Various Voting Procedures Where One Out of m Candidates (m ≥ 2) Must Be Elected"* (University of Haifa / LSE, revised 26 May 2010; Leverhulme Trust *Voting Power in Practice* workshop, Château du Baffy, Normandy). Each example becomes a live BetterVoting election plus LH-engine YAML case(s), tagged by paradox (`paradoxes:` field) and indexed in the [paradox registry](../../07_Concepts/YAML_test_case_index/PARADOX_index.md). Teaching pages: [the voting-paradoxes teaching pages](../../07_Concepts/voting_paradoxes/README.md).

## Coombs and Minimax — the cases that used to be prose only

§A7 and §A10 examine two procedures no tabulator in this repo could count, so for a long time their examples existed only as ballot profiles written out in a sentence. They are now **runnable case files**, counted by two tools that wrap Eric Pacuit's `pref_voting` and cross-check against it on every run: [`coombs_report.py`](../../STARVote_LH_tabulation_engine/tools_adam/pref_voting_tabulation_engine/coombs_report.py) and [`minimax_report.py`](../../STARVote_LH_tabulation_engine/tools_adam/pref_voting_tabulation_engine/minimax_report.py). All 18 counts reproduce Felsenthal's published results, with the single documented exception noted for Ex.31.

None of these are BV-backed: BetterVoting offers neither method, and several are deliberately indeterminate (Ex.32 and Coombs Ex.21 end in genuine ties, which is the lesson). Each file is tabulated under a supported method for its `_tabulated` mirror — Minimax cases as **Ranked Robin**, because the pairwise matrix is exactly what Minimax reads, and Coombs cases as **RCV-IRV**, the mirror-image count Coombs inverts.
